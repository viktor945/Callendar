# Вдвоём

Адаптивный сайт для пары: общий календарь с двумя видами учёта — свидания и интимная жизнь. Есть выбор формата отношений, независимые планы и факты близости, статистика регулярности, идеи разнообразия, история, личные заметки и оценки. Общие принципы вдохновлены TimeTree, Cupla, Intimassy и xTracker; интерфейс и реализация собственные.

## Посмотреть без установки

[Открыть интерактивный предпросмотр](https://htmlpreview.github.io/?https://github.com/viktor945/Callendar/blob/main/docs/index.html)

Нажмите **«Изменить формат» → «Мы пара / в браке»**, чтобы увидеть акцент на интимной жизни, или откройте раздел **«Интимная жизнь»**. Можно создавать оба типа встреч, добавлять факт без точного времени, выбирать метки и идеи, смотреть регулярность, пробовать личные заметки и оценки. Регистрация и платный хостинг не нужны. Все изменения находятся в памяти текущей вкладки и исчезают после перезагрузки. Подключение пары и синхронизация доступны только в серверной версии.

`docs/index.html` содержит стили, JavaScript, шрифты и иконку внутри файла, без запросов к API. Чтобы обновить его после правок:

```bash

```

Для собственного адреса GitHub Pages в настройках репозитория выберите **Pages → Deploy from a branch → main → /docs**. Наличие файла в репозитории само по себе не включает GitHub Pages.

## Локальный запуск

Требуется **Node.js 24+**, npm и доступ к npm registry. Внешняя база данных и ключи API не нужны.

```bash
cd /workspace/Callendar
npm ci
npm run dev
```

Приложение слушает порт **3000** на всех интерфейсах. Один процесс обслуживает React/Vite, API и SSE. Для готовой сборки:

```bash
npm run build
npm start
```

## Как пользоваться

1. Откройте сайт. Демо показывает примеры; изменения в демо находятся только в памяти вкладки.
2. Нажмите **«Создать пару»**, введите имя, выберите **«Встречаемся»** или **«Мы пара / в браке»** и создайте чистый календарь. В первом формате основной акцент — свидания, во втором — близость. Название отношений необязательно; права участников одинаковы.
3. Отправьте ссылку-приглашение партнёру. Он открывает её **в своём браузере** и вводит имя. Ссылка однократная, действует 7 дней; новое приглашение отменяет предыдущее.
4. Добавляйте и меняйте свидания и встречи близости. Фильтры **«Все встречи / Свидания / Близость»** разделяют учёт. Общий календарь обновляется у обоих через SSE. При потере связи подключение восстанавливается автоматически.
5. В разделе **«Интимная жизнь»** можно запланировать близость или **«Добавить факт»**: любой участник добавляет состоявшуюся встречу, сразу видимую обоим, без второго подтверждения. Время факта необязательно. Метки и общие пожелания видны обоим.
6. В карточке свидания нажмите **«Запланировать близость отдельно»**, чтобы создать связанную запись. Завершение свидания не завершает интимную встречу. При удалении свидания связанная близость сохраняется, её связь снимается.
7. Откройте встречу, чтобы оставить **личную заметку**, а после состоявшейся близости — необязательную личную оценку от 1 до 5. Эти поля доступны через API только с сессией автора и не входят в общие ответы или события синхронизации.
8. Нажмите **«Встреча состоялась»**, чтобы сохранить момент в истории. Статистика интимной жизни считает только состоявшиеся встречи за последние 28 дней; будущие планы показаны отдельно.
9. **«Изменить формат»** меняет общий акцент без потери записей. По желанию задайте общую частоту близости; по умолчанию цели нет. Изменения настроек также синхронизируются и защищены версией.

Встречи хранят локальные дату и время, без автоматической конвертации старых записей. «Сегодня» и период статистики определяются в зоне `Asia/Almaty` (UTC+5); настройка зоны пары запланирована отдельно. При одновременном редактировании версия встречи предотвращает потерю правки партнёра.

Обновление БД добавляет только таблицы настроек и приватных оценок; существующие события, сессии и заметки сохраняются. Старые записи без типа отображаются как свидания, прежнее текстовое продолжение не становится фактом близости автоматически.

Полный конструктор приглашений из архива с ветвлениями, десятью атмосферами, ответами получателя и аккаунтами для повторного входа ещё не реализован. Его требования и этапы описаны в [плане интеграции](docs/DATE_MODULE_INTEGRATION_PLAN.md).

## Проверки

```bash
npm test
npm run build
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

Если системного Chromium нет, установите браузер Playwright через `npx playwright install chromium` и выполните `npm run test:e2e`. В облачной среде Chromium уже доступен.

Серверные проверки покрывают подключение партнёра, настройки отношений, оба типа встреч, SSE, изоляцию заметок и оценок, связи событий, версии, проверку ввода, обновление старой БД и сохранение после перезапуска. Браузерные проверки проходят сценарии двух партнёров на компьютере и телефоне. Они запускают отдельный сервер на порту 3100 с временной БД и не изменяют ваши встречи. Скриншоты находятся в игнорируемой папке `test-results/`; отдельные результаты статического просмотра — в `preview-test-results/`.

## Данные и размещение

### Развёртывание на Render

В корне есть `render.yaml`: Node.js 24, сборка, запуск, проверка состояния и постоянный диск на 1 ГБ. **Blueprint выбирает платный тариф Starter и диск; перед созданием ознакомьтесь с актуальной стоимостью Render.** Бесплатный Web Service без постоянного диска не подходит для хранения вашего календаря: данные могут теряться при перезапусках.

1. Создайте аккаунт на [Render](https://render.com/) и подключите GitHub.
2. Выберите **New → Blueprint** и репозиторий `viktor945/Callendar`, ветку `main`.
3. Проверьте предложенные услуги и стоимость, затем запустите развёртывание.
4. После успешной сборки Render выдаст HTTPS-адрес сервиса. Сервер использует `RENDER_EXTERNAL_URL`, чтобы правильно проверять Origin и выставлять Secure-cookie. Для собственного домена установите `PUBLIC_ORIGIN`.
5. Откройте адрес, создайте пару и отправьте приглашение партнёру. После обновления сервиса календарь останется на подключённом диске.

Автоматическое развёртывание в blueprint отключено: новые изменения запускаются вручную из панели. Пароли, приглашения, SQLite и `.env` не отправляются в GitHub.

### Переменные и хранение

SQLite по умолчанию находится в `.data/calendar.sqlite`; папка исключена из Git. Не удаляйте её при обновлении. Для размещения нужен постоянно работающий **Node-сервер с постоянным диском** — статического хостинга недостаточно.

| Переменная | Назначение |
| --- | --- |
| `PORT` | Порт сервера, по умолчанию `3000` |
| `DATABASE_PATH` | Путь к SQLite на постоянном диске |
| `PUBLIC_ORIGIN` | Канонический адрес сайта, например `https://calendar.example.com`, без завершающего `/` |

На публичном сервере настройте HTTPS и `PUBLIC_ORIGIN`; это включает Secure-cookie и проверку источника изменяющих запросов. Прокси должен передавать SSE без буферизации и поддерживать долгие соединения. Для резервной копии остановите сервер и скопируйте папку БД целиком, включая WAL-файлы, если они присутствуют.

Это первая версия с входом по однократному приглашению и сессиями браузера. Сессия действует 180 дней; восстановления после очистки cookie, входа на новом устройстве и смены партнёра пока нет. Не очищайте cookie рабочего календаря. Приглашение даёт доступ к общим данным, поэтому передавайте его лично. Личные заметки разделены на уровне API, но **не зашифрованы от администратора сервера**. Полноценные аккаунты и восстановление доступа нужны перед использованием как постоянного публичного сервиса.

Уведомления, импорт внешних календарей, push, повторяющиеся встречи и интеграции с упомянутыми приложениями в эту версию не входят. Никакие данные внешних сервисов не запрашиваются.

## Структура

- `src/` — React + TypeScript, адаптивный интерфейс и подключение SSE.
- `server/index.mjs` — HTTP API, сессии, приглашения и встроенная SQLite.
- `server/index.test.mjs` — серверные интеграционные проверки.
- `tests/` — браузерные сценарии Playwright и сервер с временной БД.

Используйте существующий checkout: каждая облачная задача уже изолирована, дополнительный Git worktree не нужен.

# Серверная версия без подписки GitHub

Платная подписка GitHub и покупка домена не нужны. Приложение уже содержит Node.js-сервер, SQLite, синхронизацию пары, подписки системного календаря и Web Push. Нужен отдельный сервер, который исполняет Node.js и сохраняет диск между перезапусками. GitHub Pages и HTMLPreview этого не делают.

## Бесплатное размещение

В этом репозитории нет привязки к платному хостингу. Docker Compose запускает приложение на предоставленном вами сервере, в том числе на подходящей бесплатной виртуальной машине или домашнем компьютере с публичным доступом. Бесплатность зависит от условий выбранного провайдера: постоянный диск, HTTPS, допустимый период простоя и отсутствие обязательного перехода на платный тариф надо проверить до создания сервера. Некоторые бесплатные предложения требуют проверки банковской карты или имеют ограничения по доступным ресурсам.

`render.yaml` в корне — отдельный **платный** вариант с диском. Для размещения без оплаты его не применяйте. Бесплатный сервер с временным диском не подходит для постоянного календаря: после пересоздания могут исчезнуть события, входы пары и настройки уведомлений.

## Подготовка сервера

Нужен Linux-сервер с Docker Engine и плагином Docker Compose, постоянным диском, доступными снаружи TCP-портами 80 и 443. Для сборки рекомендуется минимум 2 ГБ оперативной памяти. Внешнюю базу данных создавать не требуется.

Нужен DNS-адрес, указывающий на публичный IP этого сервера. Можно использовать бесплатное DNS-имя: покупать домен необязательно. Для временной проверки на сервере с публичным IPv4 можно попробовать имя вида `203-0-113-10.sslip.io`, заменив числа на настоящий IP. Это сторонний бесплатный DNS-сервис, его доступность и выпуск сертификата не гарантируются. Для постоянного адреса IP должен быть закреплён за сервером. Локальные адреса и адреса за NAT без входящего доступа не подходят.

## Запуск

```bash
git clone https://github.com/viktor945/Callendar.git
cd Callendar
cp deploy/server.env.example .env
```

Укажите в `.env` единственную настройку `SITE_HOST`: DNS-имя без `https://` и без пути. Пример в файле — заглушка, замените её.

```bash
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

Откройте `https://ВАШЕ_DNS_ИМЯ/api/health`: ожидается `{"ok":true}`. Затем откройте главную страницу, создайте пару и пригласите партнёра. Каждый открывает приложение в своём браузере. Начальный деморежим не означает, что сервер не работает: после создания пары появляется настоящий пустой общий календарь.

Caddy автоматически получает и обновляет TLS-сертификат. Приложение не открывает порт 3000 наружу; оно доступно через HTTPS-прокси. `PUBLIC_ORIGIN` формируется из `SITE_HOST`, чтобы работали Secure-cookie, защита изменяющих запросов, подписки календаря и пуши. Прокси поддерживает потоковую синхронизацию SSE. Журнал доступа Caddy намеренно выключен: ссылки подписки календаря содержат секретный токен.

Проверка при первом размещении:

1. Создайте план в одном браузере и проверьте появление у партнёра.
2. Выполните `docker compose restart app` и убедитесь, что события и вход сохранились.
3. На iPhone добавьте сайт на экран «Домой», откройте с иконки и включите уведомления; отправьте тест. Инструкции: [мобильная версия](MOBILE_AND_NOTIFICATIONS.md).
4. Подключите системный календарь: [календарь телефона](PHONE_CALENDAR.md). Сначала проверьте доставку напоминания на своём устройстве.

## Обновление и резервная копия

SQLite, сессии, секреты VAPID и ссылки подписок находятся в постоянном Docker-томе `app_data`. Обычные `up`, `restart` и `down` без `-v` его сохраняют. **Не запускайте `docker compose down -v`**: эта команда удаляет данные и TLS-настройки.

Перед обновлением сделайте приватную резервную копию. Команды из папки проекта:

```bash
mkdir -p .backups
chmod 700 .backups
docker compose stop app
docker compose cp app:/data ".backups/calendar-$(date +%Y%m%d-%H%M%S)"
docker compose start app
```

Если копирование завершилось ошибкой, сначала снова запустите `docker compose start app`. Не публикуйте копию: она содержит общие и личные записи, сессии и серверные ключи.

Обновление кода с сохранением томов:

```bash
git pull --ff-only
docker compose up -d --build
```

## Что не выполняется автоматически

Файлы запуска не регистрируют аккаунт хостинга, не создают виртуальную машину и не резервируют бесплатный тариф. Для размещения нужен предоставленный пользователем сервер или подключённый аккаунт провайдера. Наличие этих файлов в GitHub само по себе не публикует сервер.

# Вдвоём на телефоне: установка, приглашения и уведомления

## Что работает в публичном предпросмотре

Раздел «Секс»: 8 сфер, 24 подкатегории, 96 вариантов, поиск, случайный набор и 8 готовых настроений. Выбранные варианты переносятся в план. Можно добавить собственные варианты и необязательные названия поз. Названия из сохранённых встреч доступны для повторного выбора. Иллюстрированного справочника поз и сексуальных анимаций нет.

Все изменения в GitHub HTML Preview находятся в памяти вкладки. Настройки установки и уведомлений показывают, как будет работать приложение, но этот предпросмотр не подключён к серверу и не получает настоящие пуши.

## Два участника и общий календарь

Каждый партнёр — отдельный участник с собственной серверной сессией. Первый создаёт пару, второй подключается по однократному приглашению. Общим становится календарь, а не личность участника. Любой из двоих может создавать приглашения и общие записи. Черновики сценариев видит только автор; личные заметки и оценки — только их владелец.

Сейчас вход хранится в cookie конкретного браузера или установленного веб-приложения, до 180 дней. Логина с паролем, входа в существующую учётную запись с другого устройства и восстановления доступа пока нет. Переключение «Я — первый/второй партнёр» существует только в демо.

**Приглашение со сценарием:** автор выбирает атмосферу, настраивает страницы и нажимает «Отправить приглашение». Оно появляется во «Входящих» второго участника. В открытом приложении видны уведомление и счётчик входящих. После выбора вариантов и принятия сервер создаёт одну запись свидания; ответ с полным выбранным путём виден обоим. Начатый ответ остаётся привязан к опубликованной версии сценария.

**Прямая запись календаря:** кнопка «Запланировать свидание/секс» сразу создаёт общий план, без прохождения сценария и принятия. Добавление состоявшегося секса также сразу видно обоим. Это два разных действия с разной логикой.

## Добавить на iPhone

Требуется опубликованная серверная версия с постоянным адресом HTTPS. На iPhone:

1. Откройте сайт в Safari → «Поделиться» → «На экран Домой».
2. Откройте «Вдвоём» с созданной иконки.
3. Создайте или подключите пару **внутри установленного приложения**: его сессия может отличаться от Safari.
4. Нажмите колокольчик → «Включить уведомления» и подтвердите системное разрешение.

Для пушей необходима iOS/iPadOS 16.4 или новее и запуск приложения с экрана «Домой». На компьютере и Android установка предлагается в поддерживаемом браузере; пуши можно включить и без установки. У каждого участника собственное разрешение и подписка устройства.

Интерфейс учитывает безопасные отступы iPhone и нижнюю навигацию. Поля ввода на мобильных имеют размер шрифта 16 px, чтобы Safari не увеличивал страницу при фокусе. Manifest, иконки 192/512 px, apple-touch-icon и service worker входят в обычную сборку. Офлайн-копия личных данных не создаётся: для загрузки календаря требуется сеть.

## Какие события отправляют пуш

| Действие | Получатель |
| --- | --- |
| Публикация приглашения на свидание | Второй партнёр |
| Принятие приглашения | Автор |
| Создание, изменение или отмена запланированной встречи | Второй партнёр |
| Сохранение личной заметки, оценки или добавление состоявшейся встречи | Пуш не отправляется |
| «Отправить тест» в настройках | Устройства самого участника |

На экране блокировки заголовок всегда «Вдвоём», текст нейтральный. Пуш не содержит название или тип встречи, выбранные варианты, позы, заметки и оценки. Нажатие открывает приложение; приглашение — соответствующий сценарий после проверки сессии. Ссылки из уведомления ограничены адресом самого сайта.

Напоминаний по времени встречи пока нет. Доставка зависит от разрешений, сети и службы уведомлений устройства; успешный ответ службы не является подтверждением показа на телефоне.

## Запуск серверной версии

Используйте Node.js 24+, `npm ci`, `npm run build`, `npm start`, постоянное хранилище SQLite и HTTPS перед сервером. Переменная `PUBLIC_ORIGIN` должна содержать фактический HTTPS-адрес сайта без завершающего пути. На Render автоматически используется `RENDER_EXTERNAL_URL`, если `PUBLIC_ORIGIN` не задана. GitHub Pages обслуживает только статические файлы и не заменяет этот сервер.

Пара ключей VAPID генерируется один раз и хранится в SQLite вместе с подписками. Дополнительный аккаунт Firebase или ключ Apple Developer не нужен. Не удаляйте базу при публикации новых версий и не копируйте её в репозиторий: она содержит сессии, личные данные и приватный ключ VAPID.

Серверу нужен исходящий HTTPS-доступ к службам Web Push (Apple `*.push.apple.com`, Chrome `fcm.googleapis.com`, Firefox `updates.push.services.mozilla.com`, Edge `*.notify.windows.com`). Подписки привязаны к участнику; один адрес нельзя перепривязать к чужой сессии. Ответы 404/410 удаляют устаревшую подписку. Тайм-аут отправки — 7 секунд; сбой службы не отменяет сохранение встречи.

Проверки сервера используют подменённый транспорт отправки: проверены получатели, приватность содержимого, постоянство ключей, срок жизни подписок и однократность уведомления при повторном принятии. Браузерные проверки проверяют каталог, сохранение вариантов, адаптивность, service worker, настройки и сценарий разрешения пушей. Настоящая доставка на iPhone требует отдельной проверки на опубликованном сайте.

# Бесплатная серверная версия на Cloudflare

Проект подготовлен для **Workers**, а не статических Pages. Используется Workers Free, бесплатный адрес `workers.dev` и SQLite-backed Durable Object. D1 отдельно создавать не нужно. На этом варианте не используются Docker, Render, платные диски или покупной домен.

Официальные условия и лимиты: https://developers.cloudflare.com/durable-objects/platform/pricing/ . Бесплатный тариф имеет суточные ограничения; превышение лимита может временно остановить запросы. Платный Workers Standard для этого проекта не требуется. Не включайте платный тариф для обхода лимитов.

## Если репозиторий уже подключён

Откройте Cloudflare → **Workers & Pages** → ваш Worker → **Settings → Build** (названия пунктов могут немного отличаться).

| Поле | Значение |
| --- | --- |
| Git repository | `viktor945/Callendar` |
| Production branch | `main` |
| Root directory | корень репозитория, `/` |
| Build command | `npm run build` |
| Deploy command | `npm run deploy:cloudflare` |
| Build variable `NODE_VERSION` | `24.19.0` |

В `wrangler.jsonc` задано имя `vdvoem-calendar`. Если подключённый Worker называется иначе, укажите в Deploy command **`npm run deploy:cloudflare -- --name ИМЯ_ВАШЕГО_WORKER`**, подставив его настоящее имя. Это позволяет публиковать в уже созданный Worker без изменения репозитория. Выберите **Retry deployment / Deploy / Retry build** после сохранения настроек, чтобы собрать актуальную ветку `main`.

Установку npm-зависимостей Cloudflare выполняет перед build command. Если на выбранном экране она не предусмотрена, задайте build command `npm ci && npm run build`. Папка выходных статических файлов — `dist`, но основная публикация выполняется через Wrangler: **не используйте только загрузку папки dist**. Иначе API и общий календарь не запустятся.

Wrangler читает `wrangler.jsonc`, публикует интерфейс и API, создаёт привязку `CALENDAR` и SQLite-класс `CalendarServer` по миграции `v1`. Аккаунт, токены и идентификаторы базы в репозитории не задаются. Не добавляйте `VITE_STATIC_PREVIEW=true`: эта переменная включает демонстрационную страницу без API.

Если вы создали именно **Pages**-проект, создайте отдельный проект через **Create application → Workers → Import a repository**, выбрав этот репозиторий. Настройка одного только Pages не заменяет Worker.

## После успешной публикации

1. В Overview нажмите **Visit** и откройте адрес `https://…workers.dev`.
2. Откройте `/api/health` на том же адресе: ожидается `{"ok":true}`. `/api/runtime` должен вернуть режим `poll`.
3. На главной нажмите **Создать пару**, введите имя, создайте календарь. Начальные примеры — обычный деморежим до подключения пары, а не признак отсутствия сервера.
4. Скопируйте приглашение. Партнёр открывает его в своём браузере и входит под своим именем.
5. Добавьте встречу. У второго партнёра она появится в течение примерно 15 секунд в открытом приложении или при возвращении в него. Перезагрузка страницы сохраняет вход и события.
6. На iPhone откройте этот адрес в Safari → «Поделиться» → «На экран Домой». Откройте приложение с новой иконки и подключите пару в этом браузерном контексте. Cookie Safari и установленного приложения могут различаться: лучше выполнять первоначальное создание/подключение пары из установленного приложения, чтобы не потерять доступ к своей сессии.
7. Колокольчик → **Календарь телефона** → подключите подписку. Подписка переносит изменения только из приложения в календарь телефона; интервал обновления определяет календарь. Настройте разрешения напоминаний на телефоне.
8. Колокольчик → **Приглашения и общие планы** → включите Web Push на каждом устройстве и отправьте тест. На iPhone требуется iOS 16.4+ и запуск с экрана «Домой».

Подробнее: [системный календарь](PHONE_CALENDAR.md), [мобильные уведомления](MOBILE_AND_NOTIFICATIONS.md).

## Хранение и ограничения

- Общие планы, приватные заметки, сценарии, сессии, ключи Web Push и ссылки подписок хранятся в постоянном SQLite-хранилище Durable Object. Перезапуск Worker и обычное обновление кода не удаляют базу.
- Не удаляйте Worker, привязку `CALENDAR` или класс `CalendarServer` и не меняйте имя объекта `calendar-server-v1`: это может отключить доступ к имеющимся данным. Не сбрасывайте миграции после первой публикации.
- В рамках одного экземпляра сайта хранятся все созданные пары; запросы ограничены своей парой, личные записи — своим участником. Хранилище не является сквозным шифрованием от администратора Cloudflare/сайта.
- Вход основан на cookie браузера сроком 180 дней. Восстановление после очистки cookie пока не реализовано. Установите приложение на телефон **до** создания пары и не очищайте его данные.
- Демо-изменения из старой вкладки HTMLPreview в серверный календарь автоматически не переносятся.
- Нет постоянных SSE-соединений: клиент запрашивает состояние каждые 15 секунд, только пока страница видима, и при возвращении. Это сокращает время активности Durable Object на Free.
- Автоматическая резервная копия в другое хранилище не настроена. До использования в качестве единственного архива учитывайте ограничения восстановления доступа и резервного копирования.
- Web Push отправляется через Fetch API Cloudflare с теми же шифрованием и VAPID, что в Node-версии. Локальные проверки используют тестовую службу доставки; реальные уведомления и сертификаты проверяются на опубликованном адресе и телефоне.

## Локальная разработка

```bash
npm ci
npm run build
npm run dev:cloudflare
```

Wrangler использует локальное постоянное хранилище `.wrangler/`; эта папка исключена из Git и Docker-контекста. На локальном HTTP доступны синхронизация и API, но подключение настоящих HTTPS-подписок и мобильных пушей проверяется после публикации.

Проверки:

```bash
npm test
npm run build
npm run test:cloudflare
CHROMIUM_PATH=/usr/bin/chromium npm run test:cloudflare:browser
```

Для публикации с собственного компьютера вместо Git-сборки:

```bash
npx wrangler login
npm run build
npm run deploy:cloudflare
```

Авторизация выполняется в браузере владельца аккаунта. Репозиторий сам по себе не даёт агенту доступ к вашей панели Cloudflare. Факт успешной локальной сборки не означает, что сайт уже опубликован: нужен успешный Deploy и проверка публичного адреса.
